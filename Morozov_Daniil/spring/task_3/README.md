# 3. Архитектура программы

## Основные модули сервера

```
server.cpp
│
├── network
│   ├── acceptLoop()      — приём клиентов
│   ├── handleClient()    — обработка клиента
│   ├── sendPacket()      — отправка данных
│   └── recvAll()         — получение данных
│
├── logging
│   ├── writeLog()        — запись в log-файл
│   └── logHistory        — история логов в памяти
│
├── monitoring
│   ├── autoLogLoop()     — авто-рассылка клиентам
│   ├── getCPUTemp()      — температура CPU
│   └── getRAMUsage()     — использование RAM
│
└── sensors
    └── lastSensorValue   — последнее значение с датчика
```

---

## Потоки сервера

| Поток | Назначение |
|-------|------------|
| **Main thread** | `accept()` новых клиентов |
| **Client thread** | `handleClient()` — обработка запросов клиента |
| **autoLogLoop** | Рассылка авто-отчётов подключённым клиентам |

# 4. Протокол сообщений

## Структура сообщения

```cpp
struct MessageHeader {
    uint32_t type;   // 4 байта — тип сообщения
    uint32_t size;   // 4 байта — размер данных
};
```

**Формат пакета:**
```
[Header: 8 байт][Data: size байт]
```

---

## Типы сообщений

| Код | Тип | Направление | Описание |
|-----|-----|-------------|----------|
| 1 | `Text` | Клиент → Сервер | Текстовое сообщение / данные с датчика |
| 2 | `Connect` | Клиент → Сервер | Подключение клиента с именем |
| 3 | `Disconnect` | Клиент → Сервер | Отключение клиента |
| 4 | `LogRequest` | Клиент → Сервер | Запрос логов |
| 5 | `LogResponse` | Сервер → Клиент | Ответ с логами |
| 6 | `StatusRequest` | Клиент → Сервер | Запрос статуса CPU/RAM |
| 7 | `StatusResponse` | Сервер → Клиент | Ответ со статусом |
| 8 | `Warning` | Сервер → Клиент | Предупреждение о превышении порога |
| 9 | `AutoLogStart` | Клиент → Сервер | Запуск авто-отчётов |
| 10 | `AutoLogStop` | Клиент → Сервер | Остановка авто-отчётов |

---

## Формат сообщений

### Сообщение клиента
```
[username HH:MM:SS] message
```
**Пример:**
```
[Alex 14:20:01] Hello
```

### Сообщение сервера
```
[COLOR][username] message
```
Цвет реализован через ANSI escape-коды (для консоли).

# 5. Работа с логами

Сервер создаёт **один файл логов**: `pi_monitor.log`

В него записываются:
- Подключения/отключения клиентов
- Сообщения чата
- Данные с датчиков
- События мониторинга (CPU/RAM)
- Предупреждения (WARNING)

---

## Примеры записей в логе

### Подключение клиента
```
[2026-05-14 14:22:10] User connected: Alex
```

### Сообщение чата
```
[2026-05-14 14:22:15] [Alex 14:22:15] Привет всем!
```

### Данные с датчика
```
[2026-05-14 14:22:20] Line sensor: 520 [BLACK (Line)]
```

### Мониторинг системы
```
[2026-05-14 14:22:30] Temp: 45.5C, RAM: 28%, Line sensor: 520 [BLACK (Line)]
```

### Предупреждение
```
[2026-05-14 14:22:40] [WARNING] Temp: 72.3C, RAM: 35%, Line sensor: 520 [BLACK (Line)]
```

---

## Запрос логов через клиента

| Команда | Описание |
|---------|----------|
| `/logs all` | Все логи из истории |
| `/logs warnings` | Только записи с [WARNING] |
| `/logs last <minutes>` | Логи за последние N минут |

**Пример:**
```
/logs last 10
```
Вернёт все логи за последние 10 минут.

# 6. Мониторинг системы

Сервер каждые 1 секунду проверяет:

| Параметр | Порог WARNING |
|----------|---------------|
| **CPU Temperature** | > 70°C |
| **RAM Usage** | > 30% |

---

## Как работает мониторинг

1. **autoLogLoop()** опрашивает клиентов с флагом `autoLog`
2. Если интервал достигнут → запрашивает CPU/RAM
3. Если порог превышен → отправляет `Warning` вместо `StatusResponse`
4. Все данные записываются в лог

---

## Получение статуса вручную

Клиент может запросить статус командой:
```
/status
```

**Ответ сервера:**
```
[STATUS] Temp: 45.5C, RAM: 28%, Line sensor: 520 [BLACK (Line)]
```

# 8. Bridge.py

Python-скрипт, который соединяет Arduino с C++ сервером.

---

## Назначение

- Читает данные из USB-порта (`/dev/ttyUSB0`)
- Упаковывает в протокол сервера
- Отправляет на localhost:54000

---

## Конфигурация

```python
USB_PORT = '/dev/ttyUSB0'      # Порт Arduino
SERVER_IP = '127.0.0.1'        # IP сервера
SERVER_PORT = 54000            # Порт сервера
```

---

## Как работает

1. Подключается к C++ серверу
2. Открывает USB-порт Arduino
3. Читает строки из Serial
4. Упаковывает в формат: `[Header][Data]`
5. Отправляет на сервер

---

## Формат пакета

```python
payload = line.encode('utf-8')           # Данные с Arduino
header = struct.pack("<II", 1, len(payload))  # Type=1 (Text), Size
sock.sendall(header + payload)
```

---

## Запуск

```bash
python3 bridge.py
```

**Вывод:**
```
Ожидание сервера ./main...
Успешно подключено к C++ серверу.
Читаю данные...
```

---

## Переподключение

Если Arduino отключена:
- Скрипт ждёт появления `/dev/ttyUSB0`
- При появлении → автоматически подключается

Если сервер упал:
- Скрипт переподключается к порту 54000

## Запрос данных

| Команда | Описание |
|---------|----------|

| Команда | Описание |

# 10. Запуск

**Компиляция:**
```bash
g++ server.cpp -std=c++17 -pthread -o server
```

**Запуск:**
```bash
./server
```

**Вывод:**
```
--- Server Started on port 54000 ---
```

```cmd
cl /EHsc client.cpp ws2_32.lib
```

**Запуск:**
```cmd
client.exe
```
