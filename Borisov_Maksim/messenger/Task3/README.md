## Обзор проекта

Данная система предназначена для удалённого мониторинга состояния встраиваемой платформы на базе **Raspberry Pi 4** с подключённым датчиком чёрной линии от **Arduino Uno**. Оператор с ноутбука под управлением Windows подключается к серверу по TCP и в режиме реального времени получает данные о состоянии системы: загрузке процессора, температуре, памяти, диске и показаниях датчика.

Типичный сценарий использования — инженер, работающий с автономной машиной (например, роботом-следователем линии), которому необходимо отслеживать как состояние вычислительного узла, так и данные с периферийных сенсоров, не имея физического доступа к плате.

Взаимодействие между компонентами:

- **Arduino Uno** считывает аналоговый/цифровой сигнал с датчика чёрной линии и передаёт его на Raspberry Pi через **USB Serial (UART)** со скоростью 9600 бод.
- **Сервер на Raspberry Pi** параллельно читает данные с Serial-порта и собирает системную телеметрию. Всё это накапливается в памяти и записывается в лог-файл.
- **Клиент на Windows** подключается к серверу по TCP, отправляет текстовые команды и получает ответы в терминал.

## Описание сервера

**Файл:** `Server_linux.cpp`  
**Платформа:** Linux (Raspberry Pi OS)  
**Запуск:** `./server`

Сервер при старте запускает три независимых потока выполнения и основной цикл приёма подключений.

### Потоки выполнения

#### 1. Поток мониторинга системы (`monitoringThread`)

Запускается при старте сервера, работает непрерывно с интервалом **5 секунд** (`MONITOR_INTERVAL`). На каждой итерации собирает следующие метрики:

| Метрика | Источник данных |
|---|---|
| Загрузка CPU (%) | `/proc/stat` — вычисляется как разница счётчиков между двумя замерами |
| Использование RAM (%) | `/proc/meminfo` — `(MemTotal - MemAvailable) / MemTotal * 100` |
| Температура CPU (°C) | `/sys/class/thermal/thermal_zone0/temp` — значение делится на 1000 |
| Использование диска (%) | Вывод команды `df /` через `popen()` |
| Время работы (Uptime) | `/proc/uptime` — переводится в формат `Xд Xч Xм Xс` |

После сбора метрик поток проверяет каждое значение против пороговых констант. При превышении порога вызывается `addWarning()`, которая записывает запись одновременно в `allLogs`, `allWarnings` и в файл `server_logs.txt`.

#### 2. Поток чтения датчика (`serialReadThread`)

Открывает последовательный порт `/dev/ttyACM0` (стандартное имя для Arduino Uno на Linux) и читает данные, которые Arduino передаёт по UART. Параметры порта:

```
Скорость:       9600 бод
Биты данных:    8
Чётность:       нет
Стоп-биты:      1
Управление потоком: нет
```

Данные читаются побайтово и накапливаются в буфере до появления символа перевода строки `\n`. Каждая полная строка сохраняется в глобальную переменную `lastLineSensorValue` (защищена `sensorMutex`) и записывается в лог с тегом `[SENSOR]`. Интервал опроса порта — **50 мс**.

Если порт `/dev/ttyACM0` недоступен при старте (Arduino не подключена), поток завершается с записью ошибки в лог. Сервер при этом продолжает работу.

#### 3. Поток обработки клиента (`handleClient`)

Создаётся отдельно для каждого подключившегося клиента (максимум `MAX_CLIENTS = 5` одновременных подключений). При подключении клиенту отправляется приветственное сообщение со списком доступных команд. Далее поток находится в цикле `recv()`, ожидая команды. Каждая принятая команда логируется с тегом `[CMD]`.

### Глобальное состояние и синхронизация

| Переменная | Тип | Защита | Назначение |
|---|---|---|---|
| `allLogs` | `vector<string>` | `logsMutex` | Все записи лога в памяти |
| `allWarnings` | `vector<string>` | `logsMutex` | Только записи с тегом `[WARNING]` |
| `lastLineSensorValue` | `string` | `sensorMutex` | Последнее значение с датчика |
| `serverRunning` | `atomic<bool>` | — | Флаг работы основного цикла |
| `sensorThreadRunning` | `atomic<bool>` | — | Флаг работы потока Serial |

## Описание клиента

**Файл:** `Client.cpp`  
**Платформа:** Windows 10/11  
**Сборка:** Visual Studio 2022, проект "Консольное приложение C++"

Клиент при запуске запрашивает IP-адрес Raspberry Pi, устанавливает TCP-соединение с сервером на порту 54000 и запускает два параллельных потока.

### Потоки выполнения

**Поток приёма (`receiveThread`)** — непрерывно вызывает `recv()` и выводит полученные от сервера данные в консоль. Данные конвертируются из кодировки UTF-8 (которую использует Linux-сервер) в Windows-1251 (кодировка консоли Windows) с помощью функции `utf8_to_windows()` через WinAPI вызовы `MultiByteToWideChar` и `WideCharToMultiByte`.

**Основной поток** — читает команды из стандартного ввода (`std::getline`) и отправляет их на сервер через `send()`. После отправки команды поток делает паузу 100 мс, чтобы поток приёма успел вывести ответ сервера до появления следующего приглашения `>`.

При разрыве соединения (сервер недоступен или вернул 0 байт) `receiveThread` устанавливает `running = false`, что приводит к завершению основного цикла ввода.

## Команды управления

Команды вводятся в консоли клиента после приглашения `>` и отправляются на сервер нажатием Enter.

| Команда | Описание | Пример |
|---|---|---|
| `status` | Текущее состояние платы: CPU, RAM, температура, диск, uptime, счётчики логов и предупреждений | `status` |
| `logs` | Все записи лога за всё время работы сервера | `logs` |
| `warnings` | Только записи с тегом `[WARNING]` | `warnings` |
| `logs_last <N>` | Записи лога за последние N минут | `logs_last 30` |
| `line_sensor` | Последнее значение, полученное с датчика чёрной линии | `line_sensor` |
| `clear_warnings` | Очистить список предупреждений в памяти сервера (в файл уже записаны) | `clear_warnings` |
| `help` | Вывести список доступных команд | `help` |
| `exit` | Корректно закрыть соединение с сервером | `exit` |

## Пороговые значения и предупреждения

Пороги определены как константы в начале `Server_linux.cpp`. При превышении любого порога в лог добавляется запись `[WARNING]` и она попадает в список `allWarnings`.

| Параметр | Константа | Значение по умолчанию |
|---|---|---|
| Загрузка CPU | `CPU_WARN_THRESHOLD` | 85% |
| Использование RAM | `RAM_WARN_THRESHOLD` | 85% |
| Температура CPU | `TEMP_WARN_THRESHOLD` | 70°C |
| Использование диска | `DISK_WARN_THRESHOLD` | 90% |

Чтобы изменить порог, отредактируй соответствующую константу в коде и пересобери сервер.

Пример предупреждения в логе:
```
[2024-05-10 14:25:11] [WARNING] Высокая температура CPU: 72.4C (порог: 70.0C)
```

## Установка и запуск

### Шаг 1 — Подготовка Raspberry Pi

Установи необходимые пакеты:

```bash
sudo apt update && sudo apt install g++ -y
```

Скопируй `Server_linux.cpp` на Raspberry Pi (через WinSCP или `scp`):

```bash
# С Windows (в PowerShell или cmd):
scp Server_linux.cpp pi@192.168.1.42:/home/pi/
```

Скомпилируй сервер:

```bash
g++ Server_linux.cpp -o server -lpthread -std=c++17
```

Открой порт в файрволе:

```bash
sudo ufw allow 54000/tcp
sudo ufw enable
```

### Шаг 2 — Подключение Arduino

Подключи Arduino Uno к Raspberry Pi через USB-кабель. Убедись что порт определился:

```bash
ls /dev/ttyACM*
# Ожидаемый вывод: /dev/ttyACM0
```

Если устройство не появилось, проверь кабель или попробуй `/dev/ttyUSB0` — в этом случае измени константу `portName` в `Server_linux.cpp`.

Добавь пользователя в группу `dialout` для доступа к Serial без `sudo`:

```bash
sudo usermod -a -G dialout pi
# Перезайди в систему чтобы изменения вступили в силу
```

### Шаг 3 — Запуск сервера

Обычный запуск (с выводом логов в терминал):

```bash
./server
```

Запуск в фоне (не останавливается при закрытии SSH-сессии):

```bash
nohup ./server &
```

Просмотр логов в реальном времени:

```bash
tail -f server_logs.txt
```

Остановка сервера:

```bash
pkill server
```

### Шаг 4 — Сборка клиента в Visual Studio 2022

1. Создай новый проект: **File → New → Project → Console App (C++)**
2. Назови проект `MonitoringClient`
3. Замени содержимое `MonitoringClient.cpp` на код из `Client.cpp`
4. Убедись что стандарт C++ установлен на C++17:  
   **Project → Properties → C/C++ → Language → C++ Language Standard → ISO C++17**
5. Запусти через **Ctrl+F5**

### Шаг 5 — Подключение клиента

При запуске клиент запросит IP-адрес. Узнать IP Raspberry Pi:

```bash
hostname -I
```

Введи полученный адрес в консоли клиента. Если сервер и клиент на одной машине — нажми Enter (будет использован `127.0.0.1`).

## Формат логов

Каждая запись лога имеет следующий формат:

```
[YYYY-MM-DD HH:MM:SS] [ТЕГ] Сообщение
```

Используемые теги:

| Тег | Описание |
|---|---|
| `[INFO]` | Информационное сообщение (статус системы, события подключения) |
| `[WARNING]` | Превышен порог одного из контролируемых параметров |
| `[SENSOR]` | Получено новое значение с датчика чёрной линии |
| `[CMD]` | Получена команда от клиента |
| `[ERROR]` | Ошибка (например, недоступен Serial-порт) |

Лог-файл `server_logs.txt` сохраняется в рабочей директории сервера и дозаписывается при каждом запуске (режим `ios::app`). Файл не очищается автоматически — при необходимости его нужно удалять вручную.

## Известные ограничения

- **Кодировка.** Сервер отправляет текст в UTF-8. Клиент конвертирует его в Windows-1251 для корректного отображения кириллицы в стандартной консоли Windows. При использовании терминала с поддержкой UTF-8 (например, Windows Terminal) конвертация может давать некорректный результат.

- **Serial-порт.** Имя порта `/dev/ttyACM0` задано константой в коде. Если Arduino определяется под другим именем, требуется изменить константу `portName` в `Server_linux.cpp` и пересобрать сервер.

- **Хранение логов в памяти.** Все логи накапливаются в `allLogs` (в RAM) на протяжении всего времени работы сервера. При очень длительной работе (недели/месяцы) возможно значительное потребление памяти. Рекомендуется периодически перезапускать сервер или реализовать ограничение на количество хранимых записей.

- **Один клиент за раз на практике.** Технически сервер поддерживает до 5 одновременных клиентов, однако команда `clear_warnings` влияет на глобальное состояние и отразится на всех подключённых клиентах.

- **Нет аутентификации.** Любой клиент в сети, знающий IP и порт, может подключиться к серверу. Для использования в открытых сетях рекомендуется ограничить доступ средствами файрвола.
