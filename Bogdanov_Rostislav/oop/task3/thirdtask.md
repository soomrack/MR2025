# 1. Описание

Chat Sensor Server — это многопользовательский TCP-чат на C++, который:

- поддерживает несколько клиентов
- логирует события
- мониторит систему
- получает данные с Arduino
- генерирует WARNING при превышении порогов

# 6. Мониторинг системы

Каждые 10 секунд сервер проверяет:
- CPU temperature
- RAM usage
- System uptime
Пороговые значения:
```
CPU_TEMP_LIMIT = 70°C
RAM_LIMIT_PERCENT = 20% //для примера
```
Если значение превышено:
```
[WARNING] CPU TEMP HIGH
```
Сообщение:

- выводится в консоль
- записывается в лог
- отправляется всем клиентам

## Тестовое завышение значений (модификация прошивки)

**Важно:** В текущей версии прошивки Arduino реализована логика для принудительной генерации предупреждений.  
Каждое **10-е** и **15-е** измерение (считая от старта контроллера) значение `sensorValue` (аналоговый вход) **умножается на 10** перед отправкой на сервер. Это искусственно вызывает превышение порогов `WARNING_THRESHOLD` и позволяет проверить реакцию системы на критические показания.

Фрагмент кода Arduino:
```cpp
int measurementCount = 0;

void loop() {
  measurementCount++;
  int sensorValue = analogRead(A0);
  
  // Каждое 10-е или 15-е значение увеличиваем в 10 раз
  if (measurementCount % 10 == 0 || measurementCount % 15 == 0) {
    sensorValue = sensorValue * 10;
  }
  // ... отправка данных
}
```

Таким образом, в логах `sensor.log` периодически появляются аномально высокие значения (например, `LIGHT:3000`), что вызывает предупреждение:

```
[WARNING] SENSOR | LIGHT LIMIT (3000)
```

---

## Проверка лимитов

Пороги для датчиков (задаются в `Server.cpp`):
- TEMP > 40°C
- HUM > 100%
- LIGHT > 1200

Если лимит превышен (в том числе из-за тестового завышения), генерируется запись:
```
[WARNING] SENSOR | TEMP LIMIT (45)
```

# 8. Добавление нового сенсора

## Шаг 1. Arduino

Добавить пин:

```
#define NEW_SENSOR_PIN A3
```
Чтение:

```
int new_sensor;

void readSensors() {
new_sensor = analogRead(NEW_SENSOR_PIN);
}
```

Отправка:

```
String data = "TEMP:" + String(temperature) +
" HUM:" + String(humidity) +
" LIGHT:" + String(light) +
" NEW:" + String(new_sensor);
```
> **Примечание:** Тестовое завышение (`*10`) применяется только к `sensorValue` (основной аналоговый вход). Для нового сенсора вы можете добавить аналогичную логику по желанию.

---

## Шаг 2. Сервер (парсер)

Ничего менять НЕ нужно.

Работает универсально:
```
NAME:VALUE
```

---

## Шаг 3. Добавить правило

В server.cpp к:
```
std::map<std::string, SensorRule> sensorRules = {

    {"TEMP", {"TEMP", 26, true}},
    {"HUM",  {"HUM",  40, true}},
    {"LIGHT", {"LIGHT", 410, true}}

};
```
Добавить:
```
{"NEW", {"NEW", 500, true}}
```
---

## Шаг 4. Проверка формата

Правильно:
```
TEMP:25 HUM:50 LIGHT:300 NEW:600
```

---

## Шаг 5. Результат

При превышении (в том числе если значение было искусственно завышено):
```
[WARNING] SENSOR | NEW LIMIT (600)
```
---

## Итог

Добавление сенсора:

1. Arduino → добавить чтение
2. Arduino → добавить в Serial
3. Server → добавить в sensorRules

## Arduino

Прошивка отправляет данные:
```
TEMP:25 HUM:50 LIGHT:300
```
Сервер читает их через `/dev/ttyUSB0` (или `/dev/ttyACM0`).

**Особенность текущей версии:** Каждые 10 и 15 измерений значение LIGHT (или другого аналогового входа) умножается на 10 для тестирования системы предупреждений.

# Потоки сервера

Сервер использует несколько потоков:

- Main thread — accept клиентов
- Client thread — обработка клиента
- Command thread — команды сервера
- Monitoring thread — мониторинг системы
- Sensor thread — данные Arduino

Максимальный размер сообщения: 1 MB
